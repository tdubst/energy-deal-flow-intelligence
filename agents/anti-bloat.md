# Anti-Bloat Rules

Use the minimum effective change.

Avoid:
- Backend infrastructure before persistence is required.
- New dependencies for simple local state or styling.
- Duplicate documentation in multiple places.
- Decorative UI that does not improve diligence, ranking, confidence, or workflow speed.
- Architecture rewrites when targeted module improvements are enough.

Prefer:
- Small reusable primitives.
- Typed contracts.
- Focused local state.
- Progressive disclosure.
- Clear handoff notes.
